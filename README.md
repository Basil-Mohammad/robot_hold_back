# Why Did the Robot Hold Back?

Certified, optimization-native explanations of control-barrier-function
quadratic-program (CBF-QP) safety-filter interventions in deep reinforcement
learning for robotics.

This repository accompanies the paper *"Why Did the Robot Hold Back?
Certified, Optimization-Native Explanations of Safety-Filter Interventions
in Deep Reinforcement Learning for Robotics"* (Bilal H. Abed-alguni, Yarmouk
University). It contains the exact QP/KKT machinery, the pilot (synthetic)
experiment suite, the full-scale MuJoCo policy-driven experiment (10
training seeds), and the LaTeX source of the paper itself.

## Repository layout

```
pilot/                 Synthetic (controlled) QP experiment suite
  qp_core.py            exact active-set QP solver, multiplier intervals,
                         deletion ground truth, Gram conditioning
  scenarios.py           random / degenerate / circular-obstacle scenario generators
  exp1_identities.py      RQ: numerical identity verification
  exp2_attribution.py     RQ1/RQ2: attribution faithfulness vs. baselines
  exp3_counterfactual.py  RQ3: certified counterfactual validation
  exp4_stability.py       RQ4: conditioning vs. empirical instability
  make_plots.py           figure generation
  pilot_report.tex/.pdf   standalone pilot report

full_experiments/
  envs/
    qp_core.py             same exact solver, reused verbatim
    maze_layout.py          occupancy-grid maze construction (moderate complexity)
    build_mjcf.py            MuJoCo MJCF scene generation
    safe_maze_env.py          Gymnasium SafeMazeEnv with CBF-QP filter in the loop
    train_ppo.py               PPO training entry point (stable-baselines3)
    collect_rollouts.py         policy rollout -> QP instance dataset
    run_full_analysis.py        RQ1-RQ4 analysis on the real, policy-driven dataset
    make_full_plots.py          figure generation
  models/                 trained PPO policies (10 seeds) + training logs
  figures/                generated result figures
  results/                summary JSONs (large per-instance CSV/pickle files
                           are regenerated by running the pipeline; they are
                           not stored in this repository, see below)
  run_all_seeds.sh        sequential 10-seed training driver

```

## Reproducing the results

```bash
pip install -r requirements.txt

# 1. Pilot (synthetic) experiments — fast, no MuJoCo required
cd pilot
python exp1_identities.py
python exp2_attribution.py
python exp3_counterfactual.py
python exp4_stability.py
python make_plots.py

# 2. Full-scale MuJoCo experiment (10 seeds; ~40 min on 2 CPU cores)
cd ../full_experiments/envs
bash ../run_all_seeds.sh                 # trains PPO for seeds 0-9
python collect_rollouts.py               # rollout -> QP instance dataset
python run_full_analysis.py              # RQ1-RQ4 on the real dataset
python make_full_plots.py                # figures
```

Large intermediate artifacts (`rollout_qp_dataset.pkl`, the per-instance
`real_attribution.csv` / `real_counterfactual.csv` / `real_stability.csv`)
are regenerated by the commands above rather than versioned in git, to keep
the repository lightweight; the summary JSON files that the paper's numbers
are drawn from are included under `full_experiments/results/`.

## Additional experiments (post-hoc baselines, overhead, ablations, generalization)

Four extra scripts in `full_experiments/envs/` reproduce the results in the
paper's Sections "Comparison with Post-Hoc Explainers", "Computational
Overhead", "Ablation Study Results", and "Generalization to Non-Circular
Constraints". They all read the same `rollout_qp_dataset.pkl` produced by
`collect_rollouts.py` above, so run them after step 2:

```bash
cd full_experiments/envs

# Table VII: SHAP / LIME / saliency / decision-tree surrogate / rule-based
# baselines vs. the proposed method, scored against the same deletion
# ground truth used throughout the paper.
python real_baselines.py            # -> ../results/real_baselines_summary.json

# Table VIII: wall-clock QP-solve / attribution / counterfactual timing as
# a function of the number of active constraints p, compared to the 0.05 s
# (20 Hz) control period.
python benchmark_overhead.py        # -> ../results/overhead_benchmark.json

# Table IX: the five ablations proposed in the Ablation Studies subsection
# (naive multiplier sign, single-multiplier without intervals, certified
# counterfactual without the closed-form re-derivation, etc.), run on a
# mixture of random and deliberately-degenerate synthetic scenarios so the
# ablations are not trivially saturated.
python ablation_studies.py          # -> ../results/ablation_summary.json

# Table X: an affine half-space CBF formulation of the maze walls (instead
# of the circular approximation used in the main experiment), mixed with
# the unchanged circular pillar constraints, re-evaluated on the SAME real
# (position, action) pairs from the already-trained policies -- a
# constraint-type generalization check that requires no retraining.
python halfspace_generalization.py  # -> ../results/halfspace_generalization_summary.json
```

Their summary JSONs are already included under `full_experiments/results/`
so the paper's numbers can be inspected without re-running anything.

## Numerical identities

The CBF-QP solver, multiplier-interval computation, and constraint-deletion
ground truth (`qp_core.py`) are implemented independently of any commercial
solver, via exact active-set enumeration, and cross-validated against SciPy
SLSQP (max discrepancy on 200 trials: `1.75e-6`).
