# Why Did the Robot Hold Back?

Certified, optimization-native explanations of control-barrier-function
quadratic-program (CBF-QP) safety-filter interventions in deep reinforcement
learning for robotics.

This repository accompanies the paper *"Why Did the Robot Hold Back?
Certified, Optimization-Native Explanations of Safety-Filter Interventions
in Deep Reinforcement Learning for Robotics"* (Bilal H. Abed-alguni, Yarmouk
University). It contains the exact QP/KKT machinery, the pilot (synthetic)
experiment suite, the full-scale MuJoCo policy-driven experiment (10
training seeds), and the LaTeX source of the paper itself.

## Reproducing the results

```bash
pip install -r requirements.txt

# 1. Pilot (synthetic) experiments — fast, no MuJoCo required
cd pilot
python exp1_identities.py
python exp2_attribution.py
python exp3_counterfactual.py
python exp4_stability.py
python make_plots.py

# 2. Full-scale MuJoCo experiment (10 seeds; ~40 min on 2 CPU cores)
cd ../full_experiments/envs
bash ../run_all_seeds.sh                 # trains PPO for seeds 0-9
python collect_rollouts.py               # rollout -> QP instance dataset
python run_full_analysis.py              # RQ1-RQ4 on the real dataset
python make_full_plots.py                # figures
```

Large intermediate artifacts (`rollout_qp_dataset.pkl`, the per-instance
`real_attribution.csv` / `real_counterfactual.csv` / `real_stability.csv`)
are regenerated by the commands above rather than versioned in git, to keep
the repository lightweight; the summary JSON files that the paper's numbers
are drawn from are included under `full_experiments/results/`.

## Additional experiments (post-hoc baselines, overhead, ablations, generalization)

Four extra scripts in `full_experiments/envs/` reproduce the results in the
paper's Sections "Comparison with Post-Hoc Explainers", "Computational
Overhead", "Ablation Study Results", and "Generalization to Non-Circular
Constraints". They all read the same `rollout_qp_dataset.pkl` produced by
`collect_rollouts.py` above, so run them after step 2:

```bash
cd full_experiments/envs

# Table VII: SHAP / LIME / saliency / decision-tree surrogate / rule-based
# baselines vs. the proposed method, scored against the same deletion
# ground truth used throughout the paper.
python real_baselines.py            # -> ../results/real_baselines_summary.json

# Table VIII: wall-clock QP-solve / attribution / counterfactual timing as
# a function of the number of active constraints p, compared to the 0.05 s
# (20 Hz) control period.
python benchmark_overhead.py        # -> ../results/overhead_benchmark.json

# Table IX: the five ablations proposed in the Ablation Studies subsection
# (naive multiplier sign, single-multiplier without intervals, certified
# counterfactual without the closed-form re-derivation, etc.), run on a
# mixture of random and deliberately-degenerate synthetic scenarios so the
# ablations are not trivially saturated.
python ablation_studies.py          # -> ../results/ablation_summary.json

# Table X: an affine half-space CBF formulation of the maze walls (instead
# of the circular approximation used in the main experiment), mixed with
# the unchanged circular pillar constraints, re-evaluated on the SAME real
# (position, action) pairs from the already-trained policies -- a
# constraint-type generalization check that requires no retraining.
python halfspace_generalization.py  # -> ../results/halfspace_generalization_summary.json
```

Their summary JSONs are already included under `full_experiments/results/`
so the paper's numbers can be inspected without re-running anything.

Two more scripts (also in `full_experiments/envs/`, also read-only against
`rollout_qp_dataset.pkl`, no retraining):

```bash
# Seed-clustered bootstrap 95% CIs + paired McNemar tests for the main
# naive/single/proposed comparison and the post-hoc-baseline comparison.
python significance_analysis.py   # -> ../results/significance_summary.json

# One-factor-at-a-time sweep of ALPHA, K_NEAREST, SAFETY_MARGIN.
python sensitivity_analysis.py    # -> ../results/sensitivity_summary.json

# Illustrative real-instance case study (Fig. 1 / Table II in the paper).
python find_case_study.py         # selects and prints the instance
python make_case_study_plot.py    # -> ../figures/fig_case_study.png

# QP-solve / attribution overhead vs. action dimension m in {2,4,6}, at
# p from m up to 12 candidate constraints (synthetic scenarios; the
# solver/attribution code is dimension-generic and unmodified).
python benchmark_overhead_highdim.py  # -> ../results/overhead_highdim_benchmark.json

# Seed-clustered bootstrap 95% CIs + paired McNemar tests for the SAC
# replication and the m=6 arm dataset (same machinery as
# significance_analysis.py, reused generically via significance_analysis.py's
# helper functions), used in the paper's SAC-vs-PPO and arm-generalization
# tables. Run after the corresponding run_full_analysis.py call above.
python significance_analysis_generic.py --dir ../results_sac --label sac
    # -> ../results/significance_summary_sac.json
python significance_analysis_generic.py --dir ../results_arm --label arm
    # -> ../results/significance_summary_arm.json
```

## Third environment: planar quadrotor (second robotic platform)

A second, structurally different environment -- an open-field planar
quadrotor navigating around 14 circular no-fly zones, rather than the
maze's corridor-and-pillar topology -- is included under the same
`full_experiments/envs/` directory, with its own trained policies
(`full_experiments/models_quad/`, 5 seeds) so it can be analyzed without
retraining:

```bash
cd full_experiments/envs

# (optional, only if you want to retrain from scratch)
bash run_all_quad_seeds.sh              # trains PPO for quad seeds 0-4

python collect_rollouts_quad.py         # -> ../results_quad/rollout_qp_dataset_quad.pkl
python run_full_analysis.py \
    --dataset ../results_quad/rollout_qp_dataset_quad.pkl \
    --outdir ../results_quad               # RQ1-RQ4 on the quadrotor dataset
python make_quad_plot.py                # -> ../figures/fig_quad_layout_training.png
```

`full_experiments/results/real_analysis_summary_quad.json` is a copy of
the quadrotor RQ1-RQ4 summary (the per-instance CSVs and the raw rollout
dataset itself are regenerated rather than versioned, as for the maze).

## Warm-started solver (real-time deployment mitigation)

```bash
cd full_experiments/envs
python benchmark_warmstart.py   # -> ../results/warmstart_benchmark.json
```
Checks that `qp_core_warmstart.solve_qp_warmstart` always agrees with the
exact enumeration solver, then benchmarks it against full enumeration on
the real chronological maze trajectories (m=2) and on synthetic
smoothly-varying sequences (m=4,6).

## Fourth environment: 6-DOF planar manipulator (higher-dimensional action space)

A third generalization environment -- `arm_env.PlanarArmEnv`, a 6-joint
planar manipulator with a genuinely 6-dimensional action space (joint
velocities), safeguarded by the same `qp_core.solve_qp` with task-space
obstacle-avoidance constraints propagated through the manipulator
Jacobian plus joint-limit constraints:

```bash
cd full_experiments/envs

# (optional, only if you want to retrain from scratch)
bash ../run_all_arm_seeds.sh            # trains PPO for arm seeds 0-2

python collect_rollouts_arm.py          # -> ../results/rollout_qp_dataset_arm.pkl
python run_full_analysis.py \
    --dataset ../results/rollout_qp_dataset_arm.pkl \
    --outdir ../results_arm                # RQ1/RQ2/RQ4 on the arm dataset
python make_arm_plot.py                 # -> ../figures/fig_arm_layout_training.png
```
`full_experiments/models_arm/` holds the 3 trained PPO policies (m=6) and
training logs; `full_experiments/results/real_analysis_summary_arm.json`
is a copy of the analysis summary used in the paper's higher-dimensional-
action-space section.

## Jacobian-aware counterfactual (RQ3 at m=6)

The closed-form counterfactual of `run_full_analysis.py` assumes the
constraint's geometry lives directly in the 2D action space, which does
not hold for the arm's joint-velocity action. `jacobian_counterfactual.py`
implements and validates the paper's Jacobian-aware generalization (which
holds exactly, not approximately, for the arm's task-space obstacle rows):
it recomputes each row's closed-form slack using the end-effector velocity
the nominal joint command induces (`v_pi = J(q) @ u_pi`), checks it against
the solver's own slack, and independently re-verifies every resulting
counterfactual certificate.

```bash
cd full_experiments/envs
python jacobian_counterfactual.py   # -> ../results/jacobian_counterfactual_summary.json
```

## Linear-barrier counterfactual (non-circular constraints)

The same closed-form idea, applied to the LINEAR (half-space) wall
constraints of `halfspace_generalization.py`'s mixed constraint-type
dataset -- even simpler than the circular case since the barrier is
already affine in position. `halfspace_counterfactual.py` computes and
independently re-verifies the certificate `d_cf = -s / alpha` for every
violated wall row on the same real mixed-constraint trajectories.

```bash
cd full_experiments/envs
python halfspace_counterfactual.py   # -> ../results/halfspace_counterfactual_summary.json
```

## LLM-based proxy comprehension study

A small, explicitly-scoped pilot (not a human-subjects study) comparing
how accurately a blinded automated rater identifies the true intervening
constraint from a naive violated-constraint report vs. the paper's
certified attribution-interval report, on 24 real maze interventions:

```bash
cd full_experiments/envs

# Builds the stratified item set + the two rater-facing prompt files
# (ground truth is kept separate so the rater never sees it).
python build_user_study_items.py
    # -> ../results/user_study_items.json (ground truth)
    # -> ../results/user_study_naive_prompt.txt
    # -> ../results/user_study_proposed_prompt.txt

# The prompt files above were each given to a fresh, independent LLM
# instance (no other context) as a rater, asked to answer every item as
# a JSON array {item_id, predicted_constraints, confidence}; the raw
# answers used in the paper are included as
# ../results/naive_answers.json and ../results/proposed_answers.json so
# the reported numbers can be reproduced without re-querying a model.

python score_user_study.py          # -> ../results/user_study_summary.json
```

## Numerical identities

The CBF-QP solver, multiplier-interval computation, and constraint-deletion
ground truth (`qp_core.py`) are implemented independently of any commercial
solver, via exact active-set enumeration, and cross-validated against SciPy
SLSQP (max discrepancy on 200 trials: `1.75e-6`).
